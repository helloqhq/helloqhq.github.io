JSON & GET Query Converter

Convert JSON objects and GET query parameters both ways locally. Supports dot/bracket nesting, URL encoding, full URLs, duplicate arrays, copy and download. No uploads or backend required.

About this tool

Convert between JSON objects and GET query parameters in one workspace. Nested JSON objects use dot notation and arrays use indexes such as [0] and [1]; the reverse conversion restores objects and arrays.

Paste a full URL, a query string with a ? prefix or bare parameters. Names and values are URL-encoded by default, including Chinese, spaces, & and =. Repeated parameters become arrays instead of being silently overwritten.

Best use cases

  • Turn JSON request samples from API documentation into GET parameters for browsers, cURL or debugging tools.
  • Restore captured URLs and log entries to JSON to inspect nesting, repeated values and empty parameters.
  • Prepare analytics, search and pagination parameters as a copy-ready query string.

How to use it

  1. Paste content into the JSON or GET parameters editor, or load the example to see both formats.
  2. Adjust URL encoding and nested restoration if needed, then select JSON → GET or GET → JSON.
  3. Review parameter counts, duplicates and skipped empty containers, then copy or download the result.

Scope and limits

  • Up to 200,000 characters, 40 nesting levels and 20,000 parameters per conversion.
  • Query values remain strings; JSON numbers, booleans and null become their textual forms.
  • Empty objects and arrays are skipped and counted. Array indexes must be continuous from 0, and conflicting paths report an error.

Data processing

JSON parsing, URL encoding and decoding, structure restoration, copying and downloading run entirely in your browser. Input is never uploaded, stored or executed.

FAQ

How are nested objects and arrays represented?

By default, filter.status=ok represents a nested object and tags[0]=json represents an array. Reverse conversion restores the structure from dots and brackets. Literal dots and brackets in JSON keys are encoded so they cannot be confused with path syntax.

Are repeated parameters lost?

No. Repeated parameters become arrays of strings, so dup=1&dup=2 becomes "dup": ["1", "2"]. If the same path is used as both a value and a container, conversion stops with a conflict error.

Is any data uploaded?

No. Parsing, encoding, nested restoration and file generation run entirely in the current browser without backend requests.
